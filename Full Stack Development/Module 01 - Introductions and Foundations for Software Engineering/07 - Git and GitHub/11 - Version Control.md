# Version Control

1. Imagine you are an author working on a manuscript for your novel. This document represents the first draft of your story.
2. As your story evolved, you might have started using sticky notes to annotate changes you wanted to make. However, this made it challenging to keep track of the overall progression and see how the story changed over time.
3. Now you have a bunch of copies with a lot of words and a lot of sticky notes. Managing these manuscritps and organizing them properly is already hard enough.

![](https://resources.metana.co/public/c8/6d/c86d3803c1fb1eadc7d0c5be7f82ead43d2bd9b5a7c4cbd893d9164a3b7439be.png)

That is why you have **Version Control**. Think of version control systems like a modern library for your manuscript. Each change you make is like a new edition of your book, and the version control system keeps track of these changes. It acts as a librarian, helping you organize and retrieve different versions of your story.

Great! you just learned one of the most important techniques in the software engineering industry that literally acts as the foundation for all the software developed around the world. However version Control concepts are not limited to code repositories or software development; they can also be applied to document management systems.

## **Centralized Vs Distributed Version Control Systems**

![](https://resources.metana.co/public/49/bd/49bd52b6d8912306f2518166b75a673dcc1e239f62957e97cd34a0e00f18bcc3.png)

![](https://resources.metana.co/public/50/08/500863d6967bbda441355151a8afe2e18e3fedb3d54b0b90ced5759d9a6a40a2.png)

Centralized Version Control (CVCS) : Imagine a traditional library where there's a central librarian managing a collection of books. Each author who wants to contribute to the library has to check out a book from the librarian, make changes, and return the updated book. Other authors can only access the latest version by checking it out from the librarian.

- SVN (Subversion) operates with a central repository model.
- Developers check out the latest version, make changes, and then commit them to the central repository.

Distributed Version Control (DVCS) : Now, imagine a group of authors working on a collaborative book. Each author has their own copy of the manuscript, and they can make changes independently. They periodically come together to merge their changes, creating a harmonized and collaborative narrative.

- Git, a distributed version control system, allows developers to have their own complete repository, and collaboration involves merging changes between repositories.

## What else can it do?

### Time Travel in Your Story

With version control, you can "time travel" through your story. Imagine being able to jump back to a specific chapter or paragraph from a month ago. Version control allows you to explore the different plot twists and character developments you've experimented with over time.

### Collaboration as Co-authors

Now, envision your manuscript evolving collaboratively with other authors. Version control systems facilitate collaboration by allowing multiple authors to work on the same story simultaneously. It's like each co-author having their own copy, making changes, and seamlessly merging them back into the master narrative.

### Branching as Alternate Endings

In version control, branching is like creating alternate endings for your story. You can experiment with different plotlines without affecting the main narrative. If a new plot twist doesn't work out, you can discard that branch and continue with the original storyline.
