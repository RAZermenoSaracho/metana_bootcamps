# Introduction to DevOps

### **What is DevOps ?**

- DevOps is a methodology emphasizing collaboration and integration between development and operations teams.
- It serves as both a methodology and a role description.
- DevOps Unifies the “Development” and “Operations” roles in software development
  - Development: Designing and building the software
  - Operations: Deployment, infrastructure, testing, monitoring

### **Infrastructure as Code**

- DevOps principle of **“infrastructure as code”** involves defining and configuring infrastructure using structured code.
- Contrastingly, traditional setup of development environments was manual and ad-hoc.
- By using code for setup, maintenance, and updates, the process becomes repeatable, automatable, and consistent.

### **Differentiating DevOps from Development**

- Development role primarily entails coding and feature implementation, while DevOps focuses on collaboration and automation between development and operations.
- DevOps engineers work on automation, deployment pipelines, and infrastructure management, necessitating a broader skill set.
- DevOps involves understanding both development and operations processes, requiring knowledge of coding, deployment, monitoring, and infrastructure management.

### **Main Principles of DevOps**

- **Automation:** Streamline processes by automating repetitive tasks.
- **Continuous Integration (CI):** Integrate code changes frequently to detect issues early.
- **Continuous Deployment (CD):** Automatically deploy code changes to production after passing automated tests.
- **Monitoring:** Continuously monitor applications and infrastructure to identify and resolve issues promptly.
- **Culture of Collaboration:** Foster communication and collaboration between development, operations, and other stakeholders.

### **What is DevSecOps ?**

- DevSecOps extends DevOps to include security practices throughout the software development lifecycle.
- It integrates security into the DevOps process to ensure security is built into every stage of development and deployment.
- Familiarity with security basics is important to mitigate risks associated with potential security breaches.

### **Why is this important to know as a Full Stack developer ?**

- As a full-stack engineer, you’re required to be able to shift fluidly between front-end and back-end roles.
- This increasingly means being able to perform deployments, maintenance, infrastructure, and setup of development and deployment environments.
- When working as a solo engineer, you need to be able to wear all the hats! You’ll not only build your application, but deploy it, maintain it, market it.
- As as solo entrepreneur, you have to perform every role from CEO to customer support, until you can hire someone to work for you.
- When you can handle a number of different roles confidently, you increase your employability and value on a team.
