# Role Based Access Control (RBAC)

RBAC assigns permissions to roles, and users are assigned roles.

### **Assigning Permissions and Roles**

- RBAC links permissions, which define what actions users can perform, to specific roles within a system.
- Users are then assigned these roles, and they may have multiple roles.
- Permissions are inherited from the roles assigned to users, simplifying access management.

### **Examples of Actions**

- Actions encompass various tasks or operations users can undertake within the system.
- Examples include creating or editing content, viewing sensitive data like sales reports, managing user accounts, or adjusting settings such as pricing.

### **Defining Roles and Abilities**

- Roles represent the abilities or actions a user can perform within the system.
- Each role is associated with specific tasks or functionalities, defining what users can do.
- For instance, roles like "CanWriteChecks" authorize users to write checks from the company bank account, while "CanDeleteUsers" grants the ability to delete user accounts.

### **Common Usage in Web Applications and Cloud Platforms**

- RBAC is a widely used access control mechanism in web applications and cloud platforms.
- It is commonly employed for managing permissions and controlling access to resources.
- For example, in AWS, RBAC governs access to resources such as S3 buckets and the objects stored within them, ensuring secure and controlled access.

Role-Based Access Control simplifies access management by organizing permissions into roles, ensuring users have appropriate access levels based on their assigned roles.
