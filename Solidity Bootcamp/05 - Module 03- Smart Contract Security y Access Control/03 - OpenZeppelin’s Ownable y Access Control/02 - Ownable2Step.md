# Ownable2Step

Explanation of ownable 2 step contract with example

Transcript for the AI

Hello everyone, and welcome back to our OpenZeppelin tutorial series. In this video, we’ll explore the Ownable2Step contract, a variant of the Ownable contract we examined previously. While the functionality is quite similar, Ownable2Step introduces a two-step process for transferring ownership, as the name suggests. We’ll use the same example contract from last time, copying it over to a new contract, updating the import and contract names, and then diving into the Ownable2Step contract to highlight its differences. First, let’s modify the contract by changing the import to Ownable2Step and updating the contract name accordingly. Now, let’s examine the Ownable2Step contract. It extends the original Ownable contract but adds a pendingOwner state variable. The transferOwnership function is overridden to set the pendingOwner instead of immediately assigning the new owner. The pending owner must then call a separate function, acceptOwnership, to officially become the contract owner. Unlike the original Ownable contract, which reverts if the zero address is passed to transferOwnership, this implementation allows it. This design provides a safety net: if a mistake is made in transferring ownership, the current owner can call transferOwnership with the zero address to reset the pendingOwner to its default, uninitialized state (the zero address), or specify the correct address to fix the error. This prevents the wrong address from taking control. However, the acceptOwnership function includes a clear restriction: only the pending owner can call it, reverting otherwise to ensure unauthorized accounts cannot assume ownership.

Now, let’s review the unit tests. The tests from the original Ownable contract remain unchanged at the top, covering the same functionality as before. However, we’ve added new tests specific to Ownable2Step. These verify that the pendingOwner is set correctly, that the pendingOwner can be the zero address (unlike in Ownable), that the pending owner can accept ownership, and that once ownership is accepted, the new owner can call protected functions. We also need to add a test to ensure a non-pending owner cannot accept ownership, which is critical for security. Let’s create this test: “Should not allow an address other than the pending owner to accept ownership.” We’ll transfer ownership to a new owner, then attempt to have a non-owner address call acceptOwnership. Since this should revert, we’ll wrap the call in an assertion expecting a reversion. Because we’re chaining asynchronous calls with Hardhat’s connect method, we need to place the expect statement before the call to ensure proper execution, using await to handle the asynchronicity. We’ll expect a custom error, OwnableUnauthorizedAccount, as defined in the Ownable2Step contract, for clarity and readability. The test logic logs the current owner, transfers ownership to the new owner, logs the new owner’s address, and attempts to have the non-owner accept ownership, which should revert.

Let’s run the unit tests with npm run test. All tests pass, confirming the contract behaves as expected.
