# Data structures

Most real contracts need to store and organise more than a single value. This section introduces Solidity's four main data structures: arrays for ordered lists, mappings for key-value lookups (the backbone of token balances and ownership records), structs for grouping related fields into a named type, and enums for representing a fixed set of states. Together, these give you the vocabulary to model almost any on-chain data model you'll encounter.

### **Arrays**

Introduces arrays in Solidity. Explains how to declare fixed-size and dynamic arrays, add or update elements, and iterate over arrays, while highlighting differences from arrays in other languages.

<https://www.youtube.com/watch?v=vTxxCbwMPwo>

### **Mappings**

Explains the mapping data type, which is a key-value store in Solidity. Demonstrates how to declare mappings (e.g., mapping(address => uint)) and use them to store and retrieve values by keys (such as tracking balances).

<https://www.youtube.com/watch?v=Q-wRG7pngn0>

### **Structs**

Covers how to define and use structs (custom data types) in Solidity. Walks through creating a struct with multiple fields and using it to group related data (for example, representing a person or a product with multiple attributes).

<https://www.youtube.com/watch?v=pQJ4TeHifdk>

### **Enums**

Explains enumeration types in Solidity. Shows how to declare an enum to represent a set of constant values (e.g., enum Status { Pending, Active, Inactive }) and use it in state variables and function logic.

<https://www.youtube.com/watch?v=5Ojnbn0rkmI>
