# What is an IPFS CID

This video from the IPFS 101 series explains what a CID (Content Identifier) is, why it’s essential in IPFS, and how it ensures secure, verifiable content addressing in decentralized systems.

[Video: What is an IPFS CID?](https://www.youtube.com/watch?v=v5sVaJFUAA8)

**Transcript for the AI**

Hello everyone, and welcome back to our IPFS 101 series! Today, we’re diving into content identifiers, or CIDs, which are fundamental to how IPFS functions and interacts with content. Unlike a typical website URL like google.com, IPFS uses CIDs, which are similar to URLs but offer much more functionality. So, what is a CID? A CID, or content identifier, is like a unique fingerprint for any content you share on IPFS. When you upload a file to an IPFS node, it runs the file through a cryptographic algorithm, similar to SHA-256, analyzing every detail to produce a CID. This process is mathematical, ensuring that the same file always generates the same CID, just like 2 + 2 always equals 4. For example, a text file containing “hello world” will produce a different CID than one with “hello world!” due to the added exclamation point. This uniqueness makes IPFS content verifiable and immutable, ensuring it hasn’t been altered. Beyond being a fingerprint, a CID also serves as the address to locate the content. Instead of visiting a webpage like google.com, you use a URL like ipfs://<CID>. This works if you’re running an IPFS node; otherwise, you can use a gateway, which we’ll cover in another video.

Now, let’s explore the implications of CIDs and why they’re significant for IPFS. One key feature is verifiability: the unique fingerprint ensures content cannot be tampered with, which is especially valuable for NFTs. NFTs are typically stored on the blockchain, but their metadata and images are too large to store on-chain, so they point to off-chain locations. Using a centralized server risks data alteration, but an IPFS CID ensures the content is immutable and decentralized, maintaining data integrity. Another powerful feature is portability, one of my favorite aspects of IPFS. Since the same file always produces the same CID, once content is on IPFS, others can pin or download it, replicating it across different IPFS nodes. For example, if I buy an NFT and its metadata and image are linked to CIDs on the blockchain, I can copy those CIDs and pin them myself, ensuring the data remains accessible on IPFS even if someone else removes it. This portability allows users to “take their ball and go home.” At Pinata, we love this because it means you can use our service and, if needed, switch to another provider or your own IPFS node by simply pinning the CIDs elsewhere. This also enables data persistence. Communities can pin valuable data, much like preserving a famous painting in a museum. For instance, the Bitcoin white paper, a critical document for crypto, can be pinned by many to ensure its longevity. NFT communities like Bored Ape Yacht Club demonstrate this by sharing CIDs in their provenance section for community pinning. In summary, CIDs are unique, verifiable fingerprints and addresses for IPFS content, enabling portability and persistence.
