# How to Persist NFT Data with IPFS

This tutorial explains how to store NFT metadata and assets using IPFS, ensuring your NFT data remains decentralized, persistent, and tamper-proof.

[Video: How to Persist NFT Data with IPFS](https://www.youtube.com/watch?v=SLfa1vUkCH0)

**Transcript for the AI**

InterPlanetary File System (IPFS) has been the primary means of persisting NFT data for years, but there’s still much work to be done, as many new Layer 1 chains and Layer 2 solutions continue to store NFT data on centralized servers. My name is Steve, and today we’ll discuss how to persist NFT data on IPFS and why it’s critical. Many NFTs in the blockchain space are at risk because they point to centralized servers for their data, which could go offline at any moment, rendering those NFTs lost. Typically, an NFT consists of a token on-chain and a pointer to off-chain data, such as images or metadata. IPFS addresses this by providing a decentralized mechanism to persist NFT data, moving away from reliance on centralized servers. There are two key perspectives to consider: creators and platforms. For creators, the choice of where to store NFT data—images, media, and metadata—is critical, as most smart contracts lock in the storage location, defined by the token URI, once deployed.

This token URI, stored on-chain, points to the external data, which could be a centralized server endpoint or an IPFS link. To use IPFS, creators can reference data in two ways. The first is the protocol URL, formatted as ipfs://<CID>, which relies on the decentralized IPFS protocol. However, pasting an ipfs:// URL into a browser typically won’t work unless an IPFS node is running locally, so marketplaces and platforms use their own gateways to render this data. This approach enhances data longevity by leveraging a decentralized protocol. The second option is a gateway link, formatted as <gateway>/ipfs/<CID>, which works immediately in browsers but depends on the gateway’s availability. If the gateway fails, the data becomes inaccessible unless the platform has tools to handle the content identifier (CID). Both methods include the CID, allowing anyone to access the data via their own IPFS node or another gateway, making either technically viable.

Creators can further ensure NFT data persistence by sharing IPFS CIDs with their communities. For IPFS content to remain online, it must be pinned, and having multiple parties pin the data—using their own storage providers or IPFS nodes—enhances decentralization and availability. Yuga Labs is a great example, and I’ll include a link in the description to their provenance section, which details how they persist NFT data. On the platform side, NFT marketplaces have a responsibility to render on-chain content correctly. When indexing a blockchain, they encounter token URIs, which may be IPFS links. Platforms can either render these server-side using gateways or choose not to display the content, though the latter is undesirable for a fast, reliable marketplace. The best approach for marketplaces is to use a dedicated gateway with IPFS gateway tools, such as those provided by Pinata. These tools allow platforms to convert any IPFS URL (protocol or public gateway) into their own gateway URL for faster, more reliable access. Dedicated gateways offer speed, built-in content delivery network (CDN) support, and on-the-fly image optimizations, keeping websites lightweight and efficient. These are just a few ways creators and platforms can collaborate to persist NFT data using IPFS.
