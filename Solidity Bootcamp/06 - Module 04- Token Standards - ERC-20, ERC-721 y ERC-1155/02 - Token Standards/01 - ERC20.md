# ERC20

Provides a tutorial on the ERC-20 token standard. Walks through writing an ERC20 token contract with standard functions like `balanceOf`, `transfer`, `approve`, and `transferFrom`. Explains how these tokens work and how they adhere to the standard interface.

**Transcript for the AI**

Hello everyone, and welcome to today’s session where we’ll code an ERC-20 token contract. The totalSupply function returns the total amount of the ERC-20 token in circulation. The balanceOf function returns the amount of tokens an account holds. A token holder can call the transfer function to send tokens to a recipient. Alternatively, if a holder wants to allow another address, referred to as a spender, to transfer tokens on their behalf, they can call the approve function to grant permission for a specific amount. To check how much a spender is allowed to transfer on behalf of a holder, you can use the allowance function. Once approved, the spender can call transferFrom to move tokens from the holder’s account to another recipient for the specified amount. Let’s now implement this ERC-20 contract, which will inherit from the IERC20 interface, ensuring we implement all required functions. We’ll start with the state variables. First, we define uint256 public totalSupply to track the total amount of tokens minted, increasing when tokens are minted and decreasing when tokens are burned. Next, we create a public mapping, mapping(address => uint256) public balanceOf, to store each account’s token balance. To handle approvals, we define another public mapping, mapping(address => mapping(address => uint256)) public allowance, where the outer key is the owner’s address, the inner key is the spender’s address, and the value is the approved amount. We also store metadata: string public name = “Test”, string public symbol = “TEST”, and uint8 public decimals = 18, where decimals indicate that 10^18 units represent one token, aligning with most ERC-20 tokens (e.g., like cents to a dollar). Attempting to compile now would fail since we haven’t implemented the required functions, so let’s copy the IERC20 interface functions and implement them.

We’ll begin with the transfer function, which allows msg.sender to send tokens to a recipient. It subtracts the specified amount from balanceOf[msg.sender] using balanceOf[msg.sender] -= amount and adds it to the recipient’s balance with balanceOf[recipient] += amount. Per the ERC-20 standard, we emit a Transfer event with emit Transfer(msg.sender, recipient, amount) and return true to indicate success. The allowance function is already handled by our public allowance mapping, so we skip it. Next, the approve function lets msg.sender approve a spender to transfer a specified amount of their tokens. We set allowance[msg.sender][spender] = amount, emit an Approval event with emit Approval(msg.sender, spender, amount), and return true for success. The transferFrom function allows anyone to transfer tokens from a sender to a recipient, provided the sender has approved msg.sender for at least the specified amount. We deduct the allowance with allowance[sender][msg.sender] -= amount, noting that Solidity 0.8’s built-in overflow/underflow checks will revert if the allowance is insufficient. We then update balances by subtracting from balanceOf[sender] and adding to balanceOf[recipient], emit a Transfer event with emit Transfer(sender, recipient, amount), and return true. Compiling now should succeed, as all required ERC-20 functions are implemented.

Currently, there’s no way to create new tokens. A mint function, typically restricted (e.g., requiring ETH or owner-only access), is needed. For simplicity, we’ll allow msg.sender to mint any amount. We define function mint(uint256 amount) external, which increments balanceOf[msg.sender] += amount and totalSupply += amount. We emit a Transfer event with emit Transfer(address(0), msg.sender, amount), indicating new tokens are created from the zero address to msg.sender. Similarly, we implement a burn function to destroy tokens, defined as function burn(uint256 amount) external. It deducts amount from balanceOf[msg.sender] and totalSupply, then emits a Transfer event with emit Transfer(msg.sender, address(0), amount), indicating tokens are sent to the zero address, removing them from circulation. While mint and burn are not part of the ERC-20 standard, they are common in most implementations. After saving, the contract compiles successfully, completing our ERC-20 token contract.
