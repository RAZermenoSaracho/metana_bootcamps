# ERC721

NFTs follow specific blockchain standards that define their behavior. The most common standard for NFTs is **ERC-721**, while **ERC-20** is used for fungible tokens. Here’s how they compare:

![](https://resources.metana.co/public/38/98/3898215339af848c5cd9c102b7d99e2e7fc8c20f70bab89d9e721470f976b4c3.png)

Covers the ERC-721 Non-Fungible Token standard. Walks through implementing an ERC721 contract (for example, a simple NFT) with functions like `mint`, `transferFrom`, and `ownerOf`. Explains how ERC721 tokens differ from ERC20 (each token is unique) and how to handle token IDs and ownership tracking.

Hello everyone, today we’ll be coding an ERC-721 contract, also known as an NFT (non-fungible token). To start, we need to declare the necessary interfaces. The first is IERC165, which supports interface detection. Next, we need IERC721, which inherits from IERC165 and defines the ERC-721 standard. Our contract, ERC721, will implement IERC721 by including all its required functions. We’ll also need the IERC721Receiver interface, which defines the onERC721Received function that must be called when using safeTransferFrom to ensure a recipient contract can handle NFTs. Let’s begin coding the ERC721 contract. We’ll start by defining the required events: Transfer, Approval, and ApprovalForAll. Next, we define the state variables. We create an internal mapping, mapping(uint256 => address) internal \_owners, where the key is the NFT’s tokenId and the value is the owner’s address. Another internal mapping, mapping(address => uint256) internal \_balances, tracks the number of NFTs each address owns. To handle approvals, we define an internal mapping, mapping(uint256 => address) internal \_approvals, where the key is the tokenId and the value is the address approved to transfer that specific NFT on behalf of the owner. For example, if an owner approves Bob to transfer NFT ID 1, \_approvals[1] stores Bob’s address. For broader permissions, we create a public mapping, mapping(address => mapping(address => bool)) public isApprovedForAll, where the outer key is the owner’s address, the inner key is the operator’s address, and the value indicates whether the operator can manage all the owner’s NFTs (true for permission, false otherwise). This mapping is public to implement the isApprovedForAll function required by IERC721. These are the minimal state variables needed for the ERC-721 contract.

Now, let’s implement the functions, starting with those required by IERC165. The supportsInterface function checks if the provided interfaceId matches IERC721 or IERC165. We return true if interfaceId == type(IERC721).interfaceId || interfaceId == type(IERC165).interfaceId. Next, we implement balanceOf and ownerOf. The balanceOf function returns the number of NFTs owned by an address, requiring that the address is not the zero address: require(owner != address(0), “owner is zero address”); return \_balances[owner];. The ownerOf function returns the owner of a tokenId, ensuring the owner is not the zero address: address owner = \_owners[tokenId]; require(owner != address(0), “owner is zero address”); return owner;. For setApprovalForAll, we allow msg.sender to grant or revoke an operator’s permission to manage all their NFTs. We set \_isApprovedForAll[msg.sender][operator] = approved, where approved is a boolean (true grants permission, false revokes it), and emit the ApprovalForAll event with emit ApprovalForAll(msg.sender, operator, approved). The approve function lets msg.sender approve an address to transfer a specific tokenId. The caller must be the owner or an approved operator: address owner = \_owners[tokenId]; require(msg.sender == owner || \_isApprovedForAll[owner][msg.sender], “not authorized”); \_approvals[tokenId] = to; emit Approval(owner, to, tokenId);. The getApproved function returns the approved address for a tokenId, requiring the token exists: require(\_owners[tokenId] != address(0), “token does not exist”); return \_approvals[tokenId];.

Next, we implement an internal helper function, \_isApprovedOrOwner, to check if a spender is the owner or has permission to transfer a tokenId. It takes address owner, address spender, and uint256 tokenId, and returns true if spender == owner || \_isApprovedForAll[owner][spender] || spender == \_approvals[tokenId]. For transferFrom, we make it public (to be reused by safeTransferFrom) and transfer a tokenId from one address to another. We verify the from address owns the token (require(from == \_owners[tokenId], “from is not owner”)), the to address is not zero (require(to != address(0), “to is zero address”)), and the caller is authorized (require(\_isApprovedOrOwner(from, msg.sender, tokenId), “not authorized”)). We update balances (\_balances[from]–; \_balances[to]++;), set the new owner (\_owners[tokenId] = to), clear approvals (delete \_approvals[tokenId]), and emit the Transfer event (emit Transfer(from, to, tokenId)). For safeTransferFrom, we call transferFrom(from, to, tokenId), then check if to is a contract by verifying if to.code.length > 0. If it is, we call IERC721Receiver(to).onERC721Received(msg.sender, from, tokenId, “”), ensuring the returned selector matches IERC721Receiver.onERC721Received.selector, or revert with “unsafe recipient”. The second safeTransferFrom variant includes a data parameter, passing it to onERC721Received instead of empty bytes.

Next, we implement non-required but useful functions: \_mint and \_burn. The internal \_mint(address to, uint256 tokenId) function requires to != address(0) (“to is zero address”) and the tokenId to be unique (require(\_owners[tokenId] == address(0), “token exists”)). It updates \_balances[to]++, sets \_owners[tokenId] = to, and emits Transfer(address(0), to, tokenId). The internal \_burn(uint256 tokenId) function verifies the token exists (address owner = \_owners[tokenId]; require(owner != address(0), “token does not exist”)), decrements \_balances[owner]–, clears \_owners[tokenId] and \_approvals[tokenId], and emits Transfer(owner, address(0), tokenId).
